# 陌生岗位快速补齐知识

面对一份陌生 JD，从零建立岗位认知，输出可直接用于学习和求职准备的完整指南。不要生成或收集面试题库。

## 工作流程

### 1. 确认输入

- 优先读取用户提供的 JD 文件或文字。
- 从上下文判断用户基础；只有无法判断且会显著影响结果时，才询问是零基础还是已有经验。
- 如果既没有 JD，也没有明确岗位名称，请用户补充其中之一。

### 2. 解析 JD

提取并逐条保留：

- 公司与团队介绍
- 工作职责
- 任职要求
- 隐含信息，例如岗位级别、协作对象、业务阶段和考核方式

生成“JD 关键词翻译表”，将术语转成新人能理解的实际工作含义，并标明对应的职责或要求。

### 3. 研究与核验

围绕以下三路进行检索：

1. 岗位基础介绍、工作内容和常见产出
2. 公司、产品、团队及行业的最新业务背景
3. 岗位核心技能、工具、方法论和知识体系

搜索词优先包含当前年份和上一年份。事实性结论应附来源；若来源受限或无法核验，明确标注。不要检索、整理或生成公开面经、历史真题、预测题、考察重点或答题框架。

### 4. 综合输出

按以下五部分组织内容，并根据用户基础调整深度：

1. **岗位基础介绍**：岗位解决的问题、价值链位置、常见产出及与相邻岗位的区别。
2. **公司、部门及业务背景**：公司与产品背景、团队目标、行业现状和竞争格局；无法核验的内部组织信息明确标注为公开信息不足。
3. **核心知识体系**：框架、模型、关键术语及其关联；术语首次出现时解释。
4. **技能拆解**：用表格列出硬技能、分析方法、软技能、重要程度及对应 JD 条目。
5. **学习路径**：按用户可用时间给出优先级明确的学习顺序、资料方向和阶段目标。

### 5. 保存成果

当用户要求生成文件，或任务本身明确包含文档交付时，将完整结果保存为 Markdown：

- 默认放在 JD 文件所在目录；没有文件时放在当前工作目录。
- 默认文件名为 `{岗位名称}完整学习指南.md`。
- 不覆盖现有同名文件，除非用户明确要求更新或覆盖。

## 质量标准

- 零基础可读：不默认用户理解专业术语。
- 紧扣 JD：关键知识和技能注明对应的职责或要求。
- 可执行：学习路径包含明确的优先级、阶段目标和可验证的业务例子。
- 保持时效：优先最新可靠资料，注明数据与事件日期。
- 不编造信息：区分公开事实、合理推断和信息缺口。
- 严守边界：不输出面试题库、历史真题、预测题或答题框架；相关任务交由其他专门 Skill 处理。
