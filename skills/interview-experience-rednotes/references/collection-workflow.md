# 面经采集流程

## 1. JD 解析

只提取公司名称、部门或业务线、岗位名称、招聘类型。不需要工作地点。保留 JD 原始用词，提取不到的信息留空，不猜测。只有公司或岗位无法判断时才询问用户。

示例：

```text
公司：滴滴
部门或业务线：滴滴国际化
岗位：金融产品经理
招聘类型：秋储实习
```

## 2. 搜索词生成

固定生成四个由精确到宽泛的搜索词。优先保留完整信息，结果不足时逐步省略招聘类型或缩短岗位名称。

```text
滴滴国际化 金融产品经理 秋储实习 面经
滴滴国际化 金融产品经理 实习 面试
滴滴 金融产品经理 面经
滴滴国际化 产品经理 面试分享
```

不要让用户逐个确认搜索词。把实际搜索词写入 `JD.md`。

## 3. 搜索与去重

- 使用默认排序。
- 每个搜索词查看前 10 条结果。
- 跳过视频类型。
- 记录搜索词、排名、note ID、标题和完整签名 URL。
- 先按 note ID 去重，再按规范化 URL 去重。
- 相同帖子命中多个搜索词时只处理一次，并记录全部命中词。
- 最多产生 40 条初始候选；不要并发打开全部候选。

## 4. 初筛

只输出“保留”或“跳过”，不使用复杂分数。

保留与目标相关且包含个人面试经历、面试流程或实际面试问题的帖子。

直接跳过：

- 明显卖课、付费咨询或辅导
- 私信、加群、领取资料等引流
- 没有个人经历的通用题库
- 与公司和岗位明显无关
- 已删除、不可见或无法读取

不要因为写得详细就声称内容真实。统一表述为“具备较强个人经历信号”或“作者自述”。

## 5. 保存来源

处理全部候选。每个通过初筛的帖子都保存，不设置 10 条上限。最终不足 8 条时提示：

> 当前检索到的相关面经较少，结果可能无法完整反映该岗位的面试情况。

不得用低相关或疑似营销内容凑数。

每帖保存标题、作者公开昵称（若可见）、note ID、完整签名 URL、发布时间、原始公开文案和全部图片。发布时间不可见时写 `未提供`。不采集评论、作者回复或其他互动数据。

## 6. OCR 与汇总

按图片顺序运行 PaddleOCR。每张图片的 OCR 结果紧跟图片展示，并标注：

> OCR 由机器生成，可能存在识别错误，请以原图为准。

从帖子原文和 OCR 中提取明确出现的面试问题。合并语义相同的问题，但保留来源引用。

面试轮次分类：AI 面、群面、一面、二面、三面、HR 面、轮次未说明。

问题类型分类：自我介绍与求职动机、简历与项目经历、岗位专业问题、业务理解、情景题与案例题、行为面试题、反问环节、其他。

只整理来源中明确出现的问题，不生成答案或预测题。

## 7. 中断与恢复

在任务目录保存已处理 note ID。遇到超时、登录失效或安全验证时：

1. 停止新请求。
2. 保留已经下载的帖子和图片。
3. 告知用户需要采取的操作。
4. 用户处理后从第一个未完成 note ID 继续。
5. 不重复下载已经验证完整的帖子。
