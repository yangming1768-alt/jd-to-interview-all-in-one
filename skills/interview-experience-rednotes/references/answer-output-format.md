# 面经回答输出格式

## 目录结构

当存在个人材料时，在原任务目录增加：

```text
个人材料索引.md
面经回答.md
面经回答.docx
面经回答.html
```

不复制原始简历，除非用户明确要求归档。`个人材料索引.md` 只保存回答所需事实及来源位置，不保存联系方式和无关隐私。

## 三格式一致性

先按 [answer-template.md](../assets/answer-template.md) 生成 `面经回答.md`，再从它生成 DOCX 和 HTML。三种版本的问题顺序、回答、状态和引用必须一致。

## 引用规则

- `[Q01]`：本回答文档中的问题锚点。
- `[P01]`、`[P01-I01]`：链接到 `面经汇总.html#P01` 或对应图片位置。
- `[R01]`、`[M01]`：链接到本回答文档末尾的个人材料依据索引。
- `[W01]`：链接到公开来源 URL，并列出标题和访问日期。

每个回答至少包含一个问题来源引用。凡使用个人经历、数字或结果，必须同时包含个人材料依据；没有依据时标记 `材料不足`。

## Word

- 使用真实标题层级、页码、可点击链接和状态标签。
- 每个 `[Qxx]` 尽量保持为一个连续区块；长回答可以分页，不压缩字号。
- 在文末附问题来源、个人材料依据和公开来源索引。
- 渲染检查分页、引用、表格或卡片、链接和溢出。

## HTML

- 使用 1180–1320px 桌面内容区和响应式单栏。
- 顶部使用单横排常驻目录，可按题型、轮次和 `[Qxx]` 跳转；空间不足时横向滚动，不换成第二行。
- 页面开头用卡片展示：岗位、问题总数、三种材料状态数量、个人材料覆盖情况。
- 每题使用独立卡片，状态标签清晰；`材料不足` 和 `需本人确认` 使用醒目但克制的提示色。
- `[Pxx]`、`[Rxx]`、`[Mxx]`、`[Wxx]` 均可点击跳转。CSS 写入 HTML，JavaScript 不是阅读所必需。

## 仅有 JD

不生成空白或泛化的 `面经回答` 文件。完成 `面经汇总` 三格式后提醒用户：可补充简历和面试准备信息，再生成有个人依据的回答。
