# 本地输出格式

## 任务目录

一个 JD 对应一个目录：

```text
{公司}_{业务线}_{岗位}_{招聘类型}/
├── JD.md
├── 面经汇总.md
├── 面经汇总.docx
├── 面经汇总.html
├── 个人材料索引.md          # 提供简历或准备材料时生成
├── 面经回答.md              # 提供个人材料时生成
├── 面经回答.docx
├── 面经回答.html
├── state.json
└── 帖子/
    ├── P01_帖子标题/
    │   ├── 帖子.md
    │   ├── metadata.json
    │   ├── ocr-results.json
    │   └── 图片/
    │       ├── 01.jpg
    │       └── 02.jpg
    └── P02_帖子标题/
        └── ...
```

清理 Windows 文件名中的 `< > : " / \\ | ? *`，去掉结尾空格和句点。标题过长时截断，但不要改变来源编号。

## `JD.md`

保存用户原始 JD 或本地文件链接、四项提取结果、四个实际搜索词和采集开始时间。使用 [jd-template.md](../assets/jd-template.md)。

## 每篇 `帖子.md`

使用 [post-template.md](../assets/post-template.md)。至少保存来源编号、标题、作者公开昵称（若可见）、发布时间、完整链接、note ID、命中搜索词、原文、全部本地图片及每张图片的 OCR。

引用编号：帖子用 `[P01]`，图片用 `[P01-I01]`。

## 三种面经汇总

先使用 [summary-template.md](../assets/summary-template.md) 生成 `面经汇总.md`，再从该文件生成 `面经汇总.docx` 和 `面经汇总.html`。Markdown 是内容基准，三个版本必须包含相同的帖子、问题分类、来源编号、原文、发布时间、来源链接、图片和 OCR，不得分别总结后产生内容漂移。

三个版本都包含两部分：

1. 常见问题汇总：按面试轮次和问题类型整理，每个问题附来源编号。
2. 全部面经：依次附每篇帖子标题、链接、发布时间、原文、图片和 OCR。

所有相对图片路径必须从 `面经汇总.md` 所在目录解析成功。

### `面经汇总.md`

- 保留可读的相对图片路径和完整签名来源 URL。
- 作为 Word 和 HTML 转换的唯一内容源。

### `面经汇总.docx`

- 使用真实 Word 标题层级、项目符号、可点击来源链接和页码。
- 所有原帖图片必须嵌入文档，不得只保留本地路径。
- 图片保持原始顺序和宽高比，不裁切；长图按页面可用区域等比缩放。
- 每篇帖子从新页开始。OCR 免责声明与对应图片保持相邻。
- 生成后渲染检查分页、图片数量、文字溢出和链接。

### `面经汇总.html`

- 生成 UTF-8、可离线打开的 HTML5 文档。
- 使用从 `面经汇总.html` 到现有 `帖子/.../图片/...` 的相对路径，不复制图片、不使用网络图片。HTML 与任务目录一起移动时必须保持目录结构。
- 使用单栏响应式阅读布局。目录放在正文上方或可折叠区域，不使用会压缩正文宽度的固定侧栏。
- 使用清晰的封面区、快速目录、章节层级和独立帖子卡片；桌面内容区建议为 1180–1320px，正文建议为 15–17px、1.7–1.9 倍行距。中等屏幕按视口缩放，手机端改为单栏；不得把电脑端正文限制在窄列中。
- 在标题后、正文前放置关键信息卡片，至少展示：部门或业务线、目标岗位、有效帖子数、按问题类型整理出的常用问题数，以及一面、二面、三面、HR 面中实际覆盖的轮次。数字必须从本次汇总动态统计，不得写死。
- 在页面顶部提供单横排常驻章节目录，至少可跳转到采集概览、按面试轮次、按问题类型和全部面经；同时提供帖子下拉目录，可直接跳转到每个 `[Pxx]`。目录不得换成第二行；空间不足时横向滚动。导航不得遮挡锚点内容。
- 将完整签名 URL 收纳为“查看小红书原帖”按钮，按钮保留完整 URL 且默认在新标签页打开，不在正文中展示超长链接。
- 将问题汇总中的每个 `[P01]`、`[P02]` 来源编号转换为可点击引用，跳转到“全部面经”中的对应帖子锚点。每篇帖子提供返回问题汇总的链接。
- 图片保持宽高比；桌面和手机宽度都不得横向溢出。
- CSS 写入 HTML 文件内部。JavaScript 不是阅读正文的必要条件；禁用脚本后仍显示全部内容。

### 转换失败

保留已生成的文件，说明失败格式和原因，修复后再交付。不要用 PDF 或网页截图替代 Word/HTML，也不要要求非技术用户手动运行转换命令。

## `metadata.json`

```json
{
  "source_id": "P01",
  "note_id": "",
  "title": "",
  "author": "",
  "published_at": "未提供",
  "source_url": "",
  "matched_queries": [],
  "post_type": "image",
  "collected_at": "",
  "screening": {"decision": "keep", "reason": ""},
  "images": []
}
```

`state.json` 只记录任务进度、已处理 note ID，以及是否已提供简历/准备信息的布尔状态；不保存个人材料正文、Cookie、token、密码或验证码。
